# Photo review comments

`GET /api/admin/photo-reviews/:reviewId/decision-events` returns up to 30 events and 30 uploads with `nextEventCursor` and `nextUploadCursor`. Request the next page with `beforeVersion` and `beforeUploadId`; pass zero for an exhausted stream. Upload IDs resolve to a sealed timestamp/ID boundary within this review, so finalization order and equal timestamps remain stable. Invalid or foreign-review upload cursors return 400 after access checks. Every page rechecks assignment and scope. `latestRejection` remains independent of paging so older comments cannot hide the current return reason. No history rows are rewritten.

`POST /api/admin/photo-reviews/:reviewId/comments` accepts the current `expectedVersion`, exact `pairRevisionId`, UUID `operationId`, and a trimmed 1–2000 character `note`. An active, scoped photo uploader, photo QC reviewer or final moderator may comment throughout the workflow, including Pending, returned and Completed reviews. Use `pairRevisionId: null` only when an initial draft has no complete pair yet. A comment on Completed leaves the approved photos locked.

The server rechecks assignment, context, version and latest pair under the track row lock. It appends a `COMMENTED` photo event and increments the track version without changing the pair or its stage. A comment does not require uploading the pair again; subsequent actions use the refreshed review version. Reusing the same operation ID and payload returns the previous result; changing the payload returns `409`. The bounded decision-events endpoint exposes comments to assigned photo staff.

The original ordered migrations add `COMMENTED`, then its same-stage event constraint. The additive `20261003110000_photo_context_comments` migration extends the allowed contexts and permits a null pair only for an initial-draft comment. Existing events, assets, graduate records and append-only protections remain. Migration and workflow exercises belong in the isolated fictional-data environment; no live migration is part of this work. Before release, validate concurrent comments/decisions, completed-review correction requests and the reviewed migration/restore procedure on representative PostgreSQL.
